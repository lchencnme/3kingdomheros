# 第三方改进计划：代码核对与执行方案

对象：`docs/三国豪杰传-商业发行改进计划.md`（第三方试玩评估，截至 2026-11-14）。
方法：逐条对照当前 `dev` 分支代码和数据，不重新试玩。

编号对照：评估里的「第 N 阵」= 代码里的 `BT_(N-1)`，第 1 阵是序战。例如第 2 阵 = BT_01 涿郡，第 6 阵 = BT_05 虎牢关，第 9 阵 = BT_08 徐州解围。

---

## 一、总体结论

**这份评估质量高，绝大部分意见合理，可以直接执行。** 它指出的问题在代码里都能找到对应原因，没有一条是凭空的。优先级划分（先规则和交互，再平衡，最后扩内容）也对。

需要修正的有三类：

1. **有 4 处事实判断不准**，见第三节。其中最重要的是：失败重试已经有了，只是文案写错让人看不出来。
2. **有 1 处比评估说的更严重**：隐藏回合上限不只是第 2 阵，20 关全部没写。
3. **有几件评估方看不到、但会影响发行的事**，见第四节。最重要的是：第 9 阵以后没有任何人真正打通过。

---

## 二、游戏现在有多少关

**21 关，全部已实现**：序战 + 第一章 5 关 + 第二章 7 关 + 第三章 8 关，讲到三顾茅庐为止。评估里说的「静态表约 21 条记录」就是这 21 关，没有空壳。

设计文档原计划共约 50 关（七章加两条结局线）。第四到第七章（约 30 关）和分支结局还没写。

**但「已实现」不等于「已验证可通关」**：自动测试走完了 21 关的流程，但测试里的胜利是直接改内存造出来的，不是真打赢的。评估方真实打通了第 1–8 阵，这是目前唯一的真实通关证据。第 9 阵（BT_08）到第 21 阵的难度和平衡没人验证过。

## 三、逐条核对

### 3.1 属实，原因已在代码里找到

| 任务 | 评估说法 | 代码核对结果 | 工作量 |
|---|---|---|---|
| T-SAVE-01 | 读档后「军议已毕」丢失 | **属实。** 这个标志只存在内存里（`camp.c` 的 `C->council`），每次进营地清零，存档结构 `SaveUi` 里没有它 | 小 |
| T-UI-01 | 地图按 Start 直接结束回合 | **属实。** `main.c:648` 直接调用 `begin_enemy_phase()` | 小 |
| T-UI-02 | 选终点时 Start 没反应 | **属实。** 该状态不处理 Start | 小 |
| T-UI-03 | 战利品舍弃、卖出无确认 | **属实。** `camp.c` 战利品页按键后立即执行 | 小 |
| T-UI-05 | 道具用前只显示名称和 n/8 | **属实。** `hud_ilist()` 只画名称和背包占用；效果值在道具表里现成有 | 中 |
| T-UI-06 | 升级只显示「升级」两个字 | **属实。** 只有 `TX_LEVELUP` 一个标签 | 中 |
| T-RULE-03 | 单挑只在开场提一次 | **属实。** 攻击预报不知道事件表 | 中 |
| T-CONT-03 | 战中商店是否存在未验证 | **没有战中商店。** 村庄、城寨格子每回合恢复兵力，仅此而已 | — |

### 3.2 比评估说的更严重

**T-RULE-01 隐藏回合上限：20 关全部没写，不只是第 2 阵。**

每一关都有回合上限（15–30 回合不等），到时未胜即败。20 段开场条件文字里，没有一段写了这个上限。评估方只在第 2 阵撞到了，其余关只是没拖到那么久。

- 最紧的是 BT_19 跃马檀溪（15 回合）和几个护送、突围关（20 回合）。
- 第 6 阵（BT_05）的「内部 30 回合」实际永远碰不到：坚守到第 12 回合就赢了。这一条不用披露，把上限改成和坚守回合一致即可，免得误解。

建议做法：不要手工改 20 段文字。让关卡生成器从数据自动在条件文字后面加一句「限 N 回合」，并且以后新关卡漏写就拒绝构建。这样第四章以后的关不会再犯。

### 3.3 事实判断不准的 4 处

1. **失败重试已经有了（T-FLOW-01）。** 败北后按 A，游戏会从开战前的快照恢复金钱、名册、物品、出阵名单，然后重打本关。问题是败北画面写的是「败北……按A重新开始」，读起来像是从头开始游戏。
   - 更正：胜利画面的「得金500」是真的，每关固定奖 500，另外还有剧情奖励。原先以为数字不符，是我看错了。
   - 真正缺的只有一半：没有「返回战前整备」这个选项。
   - 所以这一条的工作量比评估估的小：改文案 + 加一个选项。

2. **危险区的 `(x)` 不是按键（T-UI-04）。** 原文是「危险区（×）  B关闭」，`×` 指的是地图上画的叉号标记，B 键本来就写着。不过既然被读成了按键，说明文案确实有歧义，应该改成「危险区：叉号处  B关闭」之类。

3. **升级回血的规则是确定的（T-BAL-01）。** 代码里是「保留缺口」：升级前缺多少兵力，升级后还缺多少。所以兵力上限加 12，当前兵力也加 12。评估方测到的 238/328 → 250/340 正是这个规则。敌我同一套，策略值同理。
   - 这一条不需要采样验证，直接写进说明即可。
   - T-BAL-02（试验额外回血 10%–20%）是设计选择，可以以后再说。

4. **断电保护有模型验证，但没有真机验证（T-SAVE-02）。** 存档有双副本和校验。主机测试模拟了一次存档过程中 4,763 个断电时刻，没有一次坏档。这只是模型，真机和真电池卡带没测过。评估方把它列为「未知」是对的，但起点比「完全没测」好。

### 3.4 部分已经做了

- **T-ART-01 兵种辨识模板：** 今天接入的新美术已经做了一部分。11 种兵种各有剪影，具名武将带将旗，我方蓝、敌方红，另有不靠颜色的阵营标记（方块、圆、三角）和已行动标记。还没做的是评估要求的「拥挤桥头盲测」。
- **T-RULE-02 规则说明：** 游戏内没有帮助页，需要新写。

### 3.5 有冲突需要先定的

- **T-UI-04 用 Select 轮转未行动单位：** Select 在地图上已经是「中断存档」。评估也提醒了要先查按键占用。建议改成：在 Start 的确认框里加一项「下一个未行动单位」，不占新按键。

## 四、评估方看不到的问题

这些不在评估里，但会影响计划能不能执行。

1. **第 9 阵以后没人真正打通过。** 见第二节。这是最大的未知数。在修交互之前，无法判断后面 13 关是太难、太易还是有打不过的。

2. **程序空间快用完了，改功能前要先腾地方。**
   - 固定代码区（bank 0）只剩约 500 字节。评估里的确认框、预告、面板每一项都要加代码。
   - 文字区（bank 16）已用 86%，新增的提示文案会把它撑满。
   - 调用栈余量 85 字节，下限是 64。
   - 这些都能解决（把代码和文字挪到别的区），但必须先做，不然第一批改到一半就会编译不过。

3. **ROM 声明的容量是 8MB，实际只用了约 400KB。** 如果做卡带，这会白白要求大容量芯片。可以缩到 512KB。这也可能和 mGBA 黑屏有关，但没有证据，只是值得一起测。

4. **mGBA 黑屏在这边复现不了。** 这台机器只有 SameBoy，没装 mGBA。SameBoy 上之前验证过能正常运行。mGBA 需要装上再查。

5. **授权链里有一项评估没提到：** 人物画像、小兵、战斗演员是用 Grok 生成的。AI 生成图能否商用、要不要声明，需要你确认 Grok 的条款。其余部分：字体是 OFL 开源字体，音乐和地图图块是原创，开发工具 GBDK 可商用。

6. **音频我听不了。** 我只能验证节拍和数据正确，音色好不好、有没有爆音需要人听。

## 五、执行方案

顺序和评估的建议基本一致，只在前面加一步「腾空间」，并把「真实通关验证」提前。

### 第 0 批：腾空间（先做，否则后面做不了）

- 把固定代码区里的营地、战利品相关代码挪到可切换的区，目标腾出 2KB 以上。
- 文字区拆成两个区。
- 把 ROM 声明容量缩到实际需要的大小，重跑全部测试。

完成标准：固定代码区余量 ≥2KB，文字区余量 ≥30%，栈余量不降，181 项测试全过。

### 第 1 批：规则与存档可信（对应评估的 P0）

| 顺序 | 任务 | 做法 |
|---|---|---|
| 1 | T-SAVE-01 | 把「军议已毕」写进营地存档，读档时恢复 |
| 2 | T-RULE-01 | 生成器自动在每关条件后加「限 N 回合」；漏写拒绝构建；BT_05 上限改为 12 |
| 3 | T-UI-01 / T-UI-02 | Start 弹确认框（结束回合 / 下一个未行动单位 / 取消）；选终点时按 Start 给提示 |
| 4 | T-FLOW-01 | 改正胜负画面文案；败北后给两个选项：「重打本关」「回营整备」 |
| 5 | T-UI-03 / T-UI-08 | 战利品舍弃、卖出先确认；背包满时给明确提示 |

每一项都加自动测试。完成标准就是评估第 5 节写的「第一批最低验收」。

### 第 2 批：看得懂（对应评估的 P1）

- T-UI-05：道具选择行显示效果和数值（从道具表读），商店同理。
- T-UI-06：升级后弹短面板，显示等级、兵力、攻防的变化。
- T-RULE-03：能触发单挑的目标，在攻击预报里标出来。
- T-UI-04：改危险区文案；行动菜单弹出时收起「选择终点」。
- T-RULE-02 / T-BAL-01：写一页规则说明，含升级回血规则。
- T-SAVE-03：读档后显示关卡名、金钱、是否已军议。

### 第 3 批：真实验证

- **写一个会真打的自动玩家**，把 21 关按正常规则打一遍，记录每关胜负、回合数、剩余兵力。这是回答「后 13 关能不能打通」最快的办法，也顺带得到评估要的长线金钱和道具数据。
- T-SAVE-02：加测试：同一份胜利存档读 3 次，金钱和道具不增加。
- 装 mGBA 和 Emulicious 交叉测试，查黑屏。
- T-BAL-04：用上面的自动玩家重点看两个护送关，友军会不会堵住出口。

### 第 4 批：需要你决定或亲自做的

| 事项 | 为什么需要你 |
|---|---|
| 发行版收录到哪一章 | 现在只有三章。是先把三章打磨到可发行，还是继续写第四到七章，决定后面全部工作量 |
| 音频听检（T-AUD-01） | 我听不了 |
| 真机和卡带测试 | 需要实物 |
| 授权台账（T-REL-02） | 需要确认 Grok 生成图的商用条款 |
| 目标玩家盲测 | 需要真人 |
| 载体、语言、定价 | 评估第 10 节列的制作人决策 |

### 暂时不做

和评估第 8 节一致：不做战中商店，不削弱简雍，不靠加敌人兵力调难度，不默认升级回满血。在第 3 批的通关数据出来之前，不改任何数值。

## 六、对评估本身的两点补充意见

1. **评估把「第 9 阵以后全测」（T-CONT-01）排在第一批之后是对的**，但它的工作量取决于一个还没做的决定：发行版到底收录几章。建议你先定这件事。如果只发三章，T-CONT-01 就是第 3 批的自动通关；如果要发七章，那是数倍的内容工作。

2. **评估建议的盲测指标（完成率、耗时）它自己也说了不是标准。** 同意。第 1、2 批做完之前不值得找人盲测，因为现在会卡在已知问题上，得不到新信息。
